# joaccountant v8.2 — Refonte Wizard 4 étapes + Auto-création journaux + Swagger UI

**Date** : 31 juillet 2026
**Audit** : Z.ai — Analyse technique backend joaccountant v8

## Résumé des 4 phases livrées

Ce livrable contient le projet joaccountant v8 après application des 4 phases de refonte recommandées par l'audit Z.ai du 31 juillet 2026. L'audit initial a identifié trois causes racines : (1) wizard de configuration d'entreprise cassé par la migration V84 inachevée, (2) absence d'auto-création des journaux par le moteur comptable, (3) page blanche Swagger UI due à une CSP trop restrictive. Les 4 phases ci-dessous corrigent ces trois problèmes et ajoutent une architecture event-driven pour l'extensibilité future.

### Phase 1 — Quick win Swagger UI (1-2 jours)

**Problème** : L'URL `/swagger-ui.html` affichait une page blanche tandis que `/v3/api-docs` délivrait correctement le JSON OpenAPI.

**Cause racine** : La directive CSP `default-src 'none'` dans `SecurityConfig.java` ligne 69 bloquait tous les JS/CSS/webjars de Swagger UI.

**Correctifs appliqués (3 fichiers)** :

| Fichier | Correction |
|---|---|
| `app/src/main/java/jo/accountant/app/security/SecurityConfig.java` (lignes 61-96) | CSP permissive : `script-src 'self' 'unsafe-inline'`, `style-src 'self' 'unsafe-inline'`, `connect-src 'self'`, `img-src 'self' data:`, `font-src 'self' data:`, `frame-ancestors 'none'` |
| `app/src/main/resources/application-staging.yml` (lignes 54-63) | Typo `spring.doc` → `springdoc` (swagger-ui restait enabled en staging malgré l'intention contraire) |
| `app/src/main/resources/application-render.yml` (lignes 105-115) | Ajout `app.openapi.server-url` + `server-desc` (le bouton "Try it out" pointait vers localhost) |

**Test créé** : `app/src/test/java/jo/accountant/app/security/SwaggerUiCspPhase1IT.java` (9 tests)

### Phase 2 — Fix wizard V84 (1 semaine)

**Problème** : Ni le wizard 9 étapes ni le wizard 4 étapes ne fonctionnaient. La migration V84 avait clampé `wizard_step` à 4 en base, mais `Company.TOTAL_WIZARD_STEPS` restait à 9 → `completeWizard` rejetait avec `409 WIZARD_STEP_INCOMPLETE`.

**Approche radicale (suppression des anciennes approches)** :

- Suppression du wizard 9 étapes (méthodes `updateWizardStep` + 9 `applyStep*`)
- Câblage du wizard 4 étapes V8.2 (DTO orphelins enfin utilisés)
- Activation atomique en une seule transaction (modules + plan comptable + exercice + journaux + séquences + TVA)

**Fichiers modifiés/créés** :

| Action | Fichier |
|---|---|
| Constante `TOTAL_WIZARD_STEPS = 4` | `company/src/main/java/jo/accountant/company/entity/Company.java` |
| DTO enrichi (`taxRulesCreated`) | `company/src/main/java/jo/accountant/company/dto/CompanyWizardResult.java` |
| DTO typé (`vatMode: VatMode`) | `company/src/main/java/jo/accountant/company/dto/WizardStep3Request.java` |
| DTO supprimé | `company/src/main/java/jo/accountant/company/dto/WizardStepRequest.java` (supprimé) |
| Service réécrit (applyWizardStep1/2/3 + completeWizard atomique) | `company/src/main/java/jo/accountant/company/service/CompanyService.java` |
| Port créé (interface) | `company/src/main/java/jo/accountant/company/port/AccountingProvisioningPort.java` |
| Impl créée (dans :app pour éviter cycle) | `app/src/main/java/jo/accountant/app/provisioning/AccountingProvisioningPortImpl.java` |
| Contrôleur réécrit (PATCH /wizard/1, /2, /3 + POST /complete) | `company/src/main/java/jo/accountant/company/controller/CompanyController.java` |
| Bug fix : `setAllowNullValues(true)` | `core/src/main/java/jo/accountant/core/cache/CacheConfig.java` |
| Tests migrés (helper runFullWizard + 7 tests) | `app/src/test/java/jo/accountant/app/Phase1IntegrationTest.java` |
| Tests créés (11 tests atomicité/idempotence/verrouillage/ordre) | `app/src/test/java/jo/accountant/app/CompleteWizardAtomicIT.java` |

**Architecture (inversion de dépendance)** :
```
:company (interface AccountingProvisioningPort)
    ↑ implémente
:app (AccountingProvisioningPortImpl)
    ↓ dépend de
:chart-of-accounts, :accounting-engine, :document-numbering, :tax
```

### Phase 3 — Refactor Journal (1-2 semaines)

**Problème** : L'entité `Journal` était anémique (2 champs code+label, pas de type, pas de `active`). 8 modules métier faisaient chacun `orElseThrow(JOURNAL_*_NOT_FOUND)` — toute opération échouait si l'admin n'avait pas pré-créé les journaux manuellement.

**Correctifs appliqués** :

| Action | Fichier |
|---|---|
| Enum `JournalType` créé (8 valeurs VENTES/ACHATS/BANQUE/CAISSE/OD/PAIE/DEPENSES/FX) | `accounting-engine/src/main/java/jo/accountant/accountingengine/entity/JournalType.java` |
| Entité `Journal` enrichie (champs `type` + `active`) | `accounting-engine/src/main/java/jo/accountant/accountingengine/entity/Journal.java` |
| Migration V85 (ALTER TABLE + backfill type depuis code) | `accounting-engine/src/main/resources/db/migration/V85__journal_type_and_active.sql` |
| Méthode `getOrCreateJournal(companyId, JournalType)` ajoutée (idempotent, race-condition-safe) | `accounting-engine/src/main/java/jo/accountant/accountingengine/service/AccountingEngineService.java` |
| `createJournalEntry` modifié (lazy creation fallback) | idem |
| 15 occurrences remplacées dans 9 services (invoicing, purchasing, payroll, expenses, fixed-assets, inventory, funds-grants, fx-operations, FiscalYearClosingService) | 9 fichiers modifiés via pattern `getOrCreateJournal(companyId, JournalType.XX).getCode()` |

### Phase 4 — Event-driven auto-init (1 semaine)

**Problème** : `CompanyWizardCompletedEvent` était publié mais non écouté (documenté comme "YAGNI" dans `DomainEventListener`).

**Correctifs appliqués** :

| Action | Fichier |
|---|---|
| Listener `@TransactionalEventListener(AFTER_COMMIT)` sur `CompanyWizardCompletedEvent` | `chart-of-accounts/src/main/java/jo/accountant/chartofaccounts/listener/ChartOfAccountsAutoInitializer.java` |
| Listener `@TransactionalEventListener(AFTER_COMMIT)` sur `CompanyWizardCompletedEvent` | `accounting-engine/src/main/java/jo/accountant/accountingengine/listener/AccountingEngineAutoInitializer.java` |
| Dépendances Gradle ajoutées (`:chart-of-accounts` et `:accounting-engine` → `:company`) | `chart-of-accounts/build.gradle.kts`, `accounting-engine/build.gradle.kts` |
| Documentation architecture hybride (appel direct + listeners event-driven) | `company/src/main/java/jo/accountant/company/service/CompanyService.java` (Javadoc `completeWizard`) |

**Architecture hybride V8.2** : L'activation atomique est faite directement dans `completeWizard` (synchrone, même transaction). Les listeners event-driven sont des filets de sécurité idempotents + points d'extension pour de futurs modules.

## Comment démarrer

### Pré-requis
- OpenJDK 17 installé (`java -version` doit afficher 17.x)
- Pas besoin de PostgreSQL externe pour les tests (Zonky embedded)

### Compilation
```bash
cd backend_extracted
./gradlew compileJava -x test
```

### Tests
```bash
./gradlew :app:test --tests "jo.accountant.app.Phase1IntegrationTest"
./gradlew :app:test --tests "jo.accountant.app.security.SwaggerUiCspPhase1IT"
./gradlew :app:test --tests "jo.accountant.app.CompleteWizardAtomicIT"
```

### Démarrage en mode dev (avec PostgreSQL embarqué)
```bash
./gradlew :app:devRun
```
Puis ouvrir `http://localhost:8080/swagger-ui.html` (Swagger UI doit s'afficher correctement).

### Test du flux wizard 4 étapes via Swagger UI

1. `POST /api/v1/auth/register` — créer un compte
2. `POST /api/v1/auth/login` — obtenir un JWT
3. `POST /api/v1/companies` — étape 1 (name + country + functionalCurrency)
4. `PATCH /api/v1/companies/{id}/wizard/2` — étape 2 (businessTypeCode + primaryActivityLabel + sector)
5. `PATCH /api/v1/companies/{id}/wizard/3` — étape 3 (accountingFrameworkId + fiscalYearStart + vatMode)
6. `POST /api/v1/companies/{id}/wizard/complete` — étape 4 (activation atomique)
   - Réponse `CompanyWizardResult` avec : `activatedModules`, `chartOfAccountsCreated`, `fiscalYearId`, `journalCodesCreated`, `sequencesCreated`, `taxRulesCreated`
